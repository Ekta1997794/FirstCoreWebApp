1.What is MVC?
=>It is software design pattern used to organize code in the software application.
Model:- It performs:-
Business logics, Defining properties, Validations.

View:- It performs:-
Display data to the users like html, forms , controls.

Controller:- It performs:-
Co-ordinate between model and view.
Handles the buttons click
processing after submission
decide which view show in the browser.

2.Explain MVC architecture with request flow.
=> 
1.User send request
=>by click links, form submission or enter url.

2.Request Received by contoller.
=> It perform validations and decide what action to perform.

3.Controller call model=>
=> Fetch data, update data and apply business logics.

4.Model process data
=> It communicate with database , execute business logics, return result to the controller.

5.Controller select view
=> It chooses appropriate model to pass data to it.

6.View rendered response
=>receive data from controller, format and display data in (html/ui).

7.Response sent to the user.
=>Response sent back to the browser and user seems the final result.

3.Roll of controller.
=> It handles the request , when user submits the forms.
 Interact with model, perform c# logics , database communications, done some calculations, etc.
 After getting data or result , decide which view is appropriate to show and pass the data to it
and sends back the response to the browsers.

4.Diff btw View data, view bag, temp data.
=> View Data=> It stores the data in form of key value pair. Send data from controller to view. Need type casting.
Value lost when redirect to another request, hold for the current request only.
View Bag => It stores the data in form of key value pair. Send data from controller to view.No need of type casting.
Value lost when redirect to another request, hold for the current request only.
Temp Data =>  It stores the data in form of key value pair. Send data from controller to view.Need of type casting.
Value doesn't lost when redirect to another request. Stored value in Session that' why its value can be accessible in the
entire application.

18.What is Caching?
=> It is technique used in the software application to store frequently used data temporarily , so it can be reterive fastly 
instead of recomputing or fatching from the source like API and database.

Why caching is needed -

1. Without it => response slower, for every reuqest hit the database and api , server loads becomes high, etc.
2. With It => Response faster, Reduce calling database and api, improve perfomance and scalability.

Wokring process of Cache:-

1. Whenever user request to the server.
2. Firstly check in cache if present then send response from cache if not then hit database or api's.
3. Store result in cache for future requirements.
